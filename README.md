# 快记账 · money-time-ledger

一个**纯本地**的个人记账 PWA：导入微信/支付宝/银行账单，看钱花在哪、随时间攒了多少，顺带管一下基金持仓的浮盈。

数据全部存在你自己浏览器的 IndexedDB 里——**没有账号、没有服务端、没有埋点、没有第三方 CDN**。断网可用，装到桌面/手机主屏即可。

## 为什么会有这个

市面上的记账 App 大多要做两件事：让你一笔一笔手动记，或者把你的账目传到它的服务器。这个项目反过来：

- **账本来就是要导出的**：微信、支付宝、银行都能导出 CSV/xlsx，直接丢进来，不用手抄；
- **账单是隐私里的隐私**：所以它只在本机跑，连字体都不外链；
- **截图也能记**：懒得导文件的时候，截图识别走本地 OCR 模型，图片不出设备。

## 功能

**导入与对账**

- 微信支付 / 支付宝 / 银行流水的 CSV 与 xlsx 导入，自动列名探测、编码与格式兜底
- 去重指纹：同一份账单重复导入不会多入账（幂等）
- 文件合计 vs 明细合计自动对账，差额能定位到具体是哪个月、哪一笔
- 退款冲正：退款行不重复计入支出
- 跨平台重复记录检测与合并（同一笔钱在两个 App 里各记一次）

**买基金的钱不再算成支出**

把「蚂蚁财富买入」「基金定投」这类记录识别为**投资本金**，导入时改判为「不计收支」并打标签：

- 只对支出判定，且**排除词优先**（「基金从业资格考试报名」不会被误判成买入）
- 去重指纹仍按原始方向计算，重复导入不会把本金成倍入账
- 对账仍按文件原始口径计算，不会误报「差 N 元」
- 已入账的历史记录可在设置里扫描后批量改正，也可在流水里单笔改回

**截图识别（本地 OCR）**

- 记账截图 → 交易记录；持仓列表截图 → 基金持仓
- Tesseract.js 模型自托管在同源目录，深色模式截图自动反色后再识别
- 持仓列表页那种「左边名称、右边金额」的版式做了按坐标聚类的二次重组

**基金持仓**

- 持仓管理、行情刷新、净值历史序列
- 只有名称 + 市值的「占位持仓」也能先记下来，之后补份额即可算收益
- 收益算不出来时显示「待补」而不是 0（`shares × nav = 0` 会让收益变成「−成本」，那是假亏损）

**洞察与趋势**

- 洞察：分类结构、时间成本（这笔钱相当于多少工作小时）、消费复盘
- 趋势：整体收益走势（含持仓浮盈，从记账第一天累计）、收支节奏、累计利润、累计收支
- 两种累计口径分得很清：整体收益从**记账第一天**起算，其余从**区间起点**归零

**其它**

- 深色模式、移动端触控适配（16px 输入框防 iOS 缩放、safe-area）
- 备份导出 / 导入合并（JSON 与 xlsx）
- 隐私自检用例：扫描 `src/` 下所有 `fetch(` 调用，产物扫 CDN 域名必须 0 命中

## 技术栈

| 层 | 选型 |
|---|---|
| 框架 | React 18 + TypeScript strict |
| 构建 | Vite 5 + vite-plugin-pwa |
| 存储 | Dexie 4（IndexedDB），金额统一 `Cents`（branded 整数分） |
| UI | MUI 5 + Tailwind（配置少量工具类） |
| 图表 | Recharts |
| 解析 | PapaParse（CSV）+ SheetJS（xlsx） |
| OCR | tesseract.js（模型自托管） |
| 状态 | Zustand + dexie-react-hooks |
| 测试 | Vitest + jsdom + fake-indexeddb |

## 快速开始

```bash
npm install

# 可选：准备本地 OCR 模型（不跑这一步，「截图记账」不可用，其它功能不受影响）
npm run fetch:tessdata          # 下载 tessdata_best（体积大、精度高）
npm run fetch:tessdata -- --fast  # 或下载 fast 档（体积小、精度略低）

npm run dev                     # http://localhost:5173
```

生产构建与预览：

```bash
npm run build                   # tsc --noEmit && vite build
npm run preview -- --port 4173
```

## 目录结构

```
src/
  domain/     纯函数领域层：金额、日期、聚合、分类、投资浮盈、本金识别…
  db/         Dexie schema 与各表 repository
  import/     账单解析、去重、对账、OCR 预处理与版式重组
  quotes/     净值/行情获取与调度（只碰 6 位基金代码）
  export/     导出 xlsx / JSON
  backup/     备份与合并
  ui/         页面、组件、图表、主题
  test/       单元与渲染测试（含 src/test/qa 下的隐私与健壮性护栏）
docs/         产品需求、架构设计、竞品分析、类图与时序图
scripts/      资产准备脚本
server/       可选行情代理（60 行，默认不部署）
```

## 数据与隐私

- **账目不出本机**。没有登录、没有同步、没有分析服务，IndexedDB 是唯一存储。
- **不上第三方 CDN**。字体、图标、OCR 模型、wasm 全部同源；`src/test/qa/privacy.test.ts` 会扫源码里的每一个 `fetch(`，产物也会扫 CDN 域名，命中即失败。
- 运行期只有两类出网请求，且都可关：基金净值（只带 6 位基金代码）、以及为绕开跨域而可选自建的行情代理。
- 导出/备份文件由你自己保管，那才是唯一的数据副本。

## 已知限制

- **历史份额按当前份额回算**。账本没有加仓流水，所以持仓的历史收益是「一直持有现在这些份额」的近似值。
- **净值序列有限**。每次刷新最多保留约一年的历史点，更早月份的浮盈为空（图表会断线，不编数）。
- **清仓后曲线会掉一截**。卖出所得现金如果没有记进流水，整体收益就会少这一块——不替它编数字。
- **OCR 依赖截图质量**。深色模式已处理，但字太小、图片被压缩过仍会掉准确率。
- 投资本金识别靠商户名/商品名的关键词，不含「基金」二字且无平台名的行（如只有「易方达蓝筹精选混合」）会漏判，可在流水里手动改方向。

## 开发约定

- 金额只用 `Cents`（整数分），不出现浮点金额。
- **`vitest` 绿 ≠ `tsc` 绿**：Vitest 用 esbuild 剥类型，不会被类型错误挡住。提交前请跑 `npm run typecheck`。
- 收益算不出来必须是 `null`（UI 显示「待补」），不许填 0——0 会变成一笔假亏损。
- 破坏性操作一律走 `ConfirmDialog` 二次确认，异步写操作要锁按钮。
