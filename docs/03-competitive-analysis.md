## 二、四个反直觉发现

### 1. 「把支出换算成劳动时间」不是我们的原创

**HomeBank**（开源桌面记账，2000 年代起）内置 **Life Energy（生命能量）** 功能，两种换算模式：
- 按工资折算：`金额 ÷ 时薪 = 工作小时数`
- 按摊销折算：把一次性大额支出摊到使用寿命上，算出每天/每月消耗多少工作时间

这和我方「每笔支出换算成还要工作多久」在机制上几乎相同。**结论：核心机制无壁垒，壁垒只能建立在「中文账单 + 零联网 + 触达场景」上。**

### 2. 中文账单导入已经有开源项目做好了

**ezBookkeeping**（Go + Vue，自托管）原生支持解析微信支付、支付宝、中国银行、钱迹等账单，直接解决编码、表头行、金额符号问题——这正是我方历史上踩过坑的地方（分隔行识别、`收/支` 列方向静默判错）。

**飞鱼**（中文 Android 开源记账）也做微信/支付宝导入 + OCR。

**结论：中文账单导入不是空白市场，是入场券。**

### 3. 跨源对账也有开源项目做了

**值得么（zhideme）** 的核心卖点就是：同一笔消费同时出现在微信、支付宝、信用卡账单里，自动识别为同一笔并去重。

**结论：你在需求里提的「各平台相同时间类似账对账」，别人已经做了。我们要超越，必须在「判定依据的透明度」上做——让用户看见为什么判成同一笔、能一键否掉，而不是黑箱自动合并。**

### 4. 记账 App 可能让人花得更多

有用户反馈：用了记账 App 之后月支出上升到预算的 **115%**，原因是「预算还剩多少」被感知成「我还有多少钱可以花」。

**这对我们是直接警告**：「这笔咖啡 = 0.5 小时工作」如果被感知成「才半小时，不贵」，时间成本换算会反向刺激消费。

**结论：这个机制必须双向设计——不仅显示「要工作多久」，还要在累计维度显示「本月已用掉 X 个工作日」，让总量有压迫感，而不是单笔有豁免感。**

## 三、共性短板 Top 5（用户痛感 × 现有项目都没解决）

| # | 短板 | 为什么没人做好 |
|---|---|---|
| 1 | **多设备同步要么要服务器、要么靠手动导文件** | 无服务器场景下冲突合并是难题（我方这轮已解决：合并恢复 + 墓碑 + 跨设备 dedupe） |
| 2 | **对账判定是黑箱** | 做对账的项目只给结果不给依据，用户不敢信，误判后无法追溯 |
| 3 | **AI 分析要么上云、要么只能导裸 CSV** | 上云违反隐私直觉；导裸 CSV 用户不知道怎么喂给 AI |
| 4 | **投资持仓不区分平台** | 数据模型按「标的信息」建（一只基金一行），而不是按「持仓」建（支付宝一笔、天天基金一笔） |
| 5 | **报表全是被动展示，没有行为干预** | 报表是「看后视镜」，没有任何项目在花钱当下给反馈 |

## 四、我方五个可超越点

| # | 切入点 | 对标 | 超越标准 | 技术可行性 |
|---|---|---|---|---|
| 1 | **零联网可验证** | 所有自托管项目都要求服务器 | 不仅是「不联网」，而是把「无网络请求」做成可执行测试（我方已有 `privacy.test.ts` 扫描 `src/` 全部 `fetch`）。竞品没有一家能给出这个证明 | 已实现 |
| 2 | **对账判定可解释** | 值得么（黑箱） | 每条疑似配对给出判定依据（时间差 N 分钟、金额完全相同、对手方相似度），用户可一键否掉并记住「不是同一笔」 | 需新增判定打分 + 否定记忆表，中等 |
| 3 | **AI 分析零上传** | 无项目做好 | 导出「结构化数据集 + 字段词典 + 提示词模板」三件套，用户自己粘给任何 AI；导出前可选字段脱敏 | 纯前端生成 JSON，低 |
| 4 | **持仓按平台建模** | 全部按标的信息建模 | 同一只基金在支付宝/天天基金各一行，带平台标签；导入时按「平台+代码」幂等，不会互相覆盖 | 需给 `holdings` 加平台维度 + 唯一索引改造，中等 |
| 5 | **时间成本双向设计** | HomeBank 只做单向换算 | 单笔显示「要工作 X 小时」，同时顶部常驻「本月已消耗 N 个工作日」，制造总量压迫而非单笔豁免 | 纯 UI + 聚合，低 |

## 五、反面教材（明确不学）

1. **把账目上传云端做 AI 分析**（部分商业 App）：在中文隐私语境下，财务数据上云是致命信任问题。我们只导出、不上传。
2. **要求注册账号才能用**：多一个账号就多一个泄露面。
3. **静默埋点/崩溃上报**（Sentry 等）：即使「只是错误信息」，也可能带上下文。我方 `ErrorBoundary` 只打本地控制台。
4. **黑箱自动去重**：自动合并账目而不告知，一旦误判用户无法发现。必须逐条确认。
5. **只做后视镜报表**：不做行为干预的记账工具，最终会变成「记了但没用」。

## 六、结论

「快记账」的正确定位不是「功能最多的记账工具」，而是：

> **唯一一个能向你证明「它没有联网」的中文记账工具，并且把每一笔支出变成你能感受到的代价。**

三个不可替代的组合：**零联网可验证 + 中文账单原生 + 时间成本双向压迫**。单看任何一条都有竞品，三条同时具备的没有。
